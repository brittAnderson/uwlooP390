10  Handling Experimental Data

10.1 The Problem

You have run an experiment. Participants sat at your computer, responded to stimuli, and now you have data. How do you store it? How do you organize it? How do you make sure you can still read it six months from now—or share it with a collaborator who uses different software?

This chapter introduces several approaches to storing and retrieving experimental data in Python. We will use a consistent example throughout: data from a Posner cueing task. Each trial has:

  • participant_id: unique identifier
  • age: participant age in years
  • side: which side the stimulus appeared (“left” or “right”)
  • cue: which side was cued (“left” or “right”)
  • valid: whether the cue matched the stimulus location (True/False)
  • correct: whether the response was correct (True/False)
  • rt: reaction time in milliseconds

Do you know what a Posner Cuing Task is? If not, you should look it up. You cannot program or analyze what you do not understand.

10.2 The Brittle Way

A frequent and useful way to store small datafiles is as a CSV file. CSV stands for comma separated values. Each entry is separated by a comma from the next one, and the row of data is built up until the end when a newline (often indicated as \n) marks the end of one row and the return to the beginning of the next. However, there is a right way and a naive, or brittle way, to do this.

Suppose you want to save a single trial as a line in a text file. You could just manually construct this in your code like so:

participant_id = 1
age = 22
side = "left"
cue = "left"
valid = True
correct = True
rt = 342.7

# The brittle way
line = str(participant_id) + "," + str(age) + "," + side + "," + cue + "," + str(valid) + "," + str(correct) + "," + str(rt)
print(line)
1,22,left,left,True,True,342.7

This works. But consider what happens when:

  • You forget a comma
  • You put the columns in the wrong order
  • You add a new variable but forget to update the string
  • Your string value contains a comma
  • You need to read it back and parse all those types
Note

What are all those str calls doing? Why might that be inconvenient?

# Forgot the comma after age - silent bug
broken_line = str(participant_id) + "," + str(age) + side + "," + cue + "," + str(valid) + "," + str(correct) + "," + str(rt)
print(broken_line)
1,22left,left,True,True,342.7

The code runs without error, but the data is corrupted. This is the worst kind of bug: silent failure. Everything that follows in this chapter exists to prevent this class of error.

10.3 Dictionaries

A dictionary stores data as key-value pairs. The keys are names (strings), and the values can be anything. This maps naturally onto experimental data where each variable has a name.

trial = {
    "participant_id": 1,
    "age": 22,
    "side": "left",
    "cue": "left",
    "valid": True,
    "correct": True,
    "rt": 342.7
}

print(trial)
print(trial["rt"])
{'participant_id': 1, 'age': 22, 'side': 'left', 'cue': 'left', 'valid': True, 'correct': True, 'rt': 342.7}
342.7

A single trial is one dictionary. Multiple trials are a list of dictionaries:

trials = [
    {"participant_id": 1, "age": 22, "side": "left", "cue": "left", "valid": True, "correct": True, "rt": 342.7},
    {"participant_id": 1, "age": 22, "side": "right", "cue": "left", "valid": False, "correct": True, "rt": 412.3},
    {"participant_id": 1, "age": 22, "side": "left", "cue": "right", "valid": False, "correct": False, "rt": 523.1},
    {"participant_id": 2, "age": 19, "side": "left", "cue": "left", "valid": True, "correct": True, "rt": 298.4},
]

# Access the RT from the second trial
print(trials[1]["rt"])
412.3

10.3.1 Filtering Data

List comprehensions are a nice features of many programming languages, including python. The basic syntax is square brackets with a declared variable, a source for generating it and optionally some tests. For example, you could create a list of even numbers by testing a range of numbers. [x for x in range(12) if (x%2 == 0)]

You can use list comprehensions to filter:

# Get all RTs from valid trials
valid_rts = [t["rt"] for t in trials if t["valid"] == True]
print(valid_rts)

# Get all trials from participant 1
p1_trials = [t for t in trials if t["participant_id"] == 1]
print(len(p1_trials))
[342.7, 298.4]
3

10.4 CSV Files

CSV (Comma-Separated Values) is the common language of rectangular data. Excel can read it. SPSS can read it. R can read it. Every tool you will ever encounter can read CSV.

Python’s csv module is in the standard library—no installation required.

10.4.1 Writing CSV

The DictWriter class takes a list of dictionaries and writes them to a file. You specify the column names (fieldnames), and it handles the rest:

import csv

trials = [
    {"participant_id": 1, "age": 22, "side": "left", "cue": "left", "valid": True, "correct": True, "rt": 342.7},
    {"participant_id": 1, "age": 22, "side": "right", "cue": "left", "valid": False, "correct": True, "rt": 412.3},
    {"participant_id": 1, "age": 22, "side": "left", "cue": "right", "valid": False, "correct": False, "rt": 523.1},
    {"participant_id": 2, "age": 19, "side": "left", "cue": "left", "valid": True, "correct": True, "rt": 298.4},
]

fieldnames = ["participant_id", "age", "side", "cue", "valid", "correct", "rt"]

with open("posner_data.csv", "w", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writeheader()
    writer.writerows(trials)

Notice: no string concatenation, no manual commas, no str() calls. The module handles all of it. If you add a column, you add it to the dictionary and the fieldnames list—done.

In the examples above you have been writing and reading from files. Python has some nice, simple ways for handling files. Files are dealt with by something called a handler. You use open to create or open a file. When you do this there are some required fields, such as the name of the file, and the mode (read, write, both) that you want the file dealth with. Then it is customary to give it a temporary name you can use to refer to this handler. You will often see “f”, but you can use anything, e.g. posner_data_f might help you keep track of what this handle points to.

10.4.2 Reading CSV

Reading is just as clean:

with open("posner_data.csv", "r") as f:
    reader = csv.DictReader(f)
    loaded_trials = list(reader)

print(loaded_trials[0])
{'participant_id': '1', 'age': '22', 'side': 'left', 'cue': 'left', 'valid': 'True', 'correct': 'True', 'rt': '342.7'}
Warning

Notice that everything comes back as strings. CSV has no type information. The "342.7" is now the string "342.7", not the float 342.7. You must convert:

for trial in loaded_trials:
    trial["rt"] = float(trial["rt"])
    trial["age"] = int(trial["age"])
    trial["valid"] = trial["valid"] == "True"
    trial["correct"] = trial["correct"] == "True"
    trial["participant_id"] = int(trial["participant_id"])

print(loaded_trials[0])
print(type(loaded_trials[0]["rt"]))
{'participant_id': 1, 'age': 22, 'side': 'left', 'cue': 'left', 'valid': True, 'correct': True, 'rt': 342.7}
<class 'float'>

10.5 JSON

JSON (JavaScript Object Notation) is a text format that looks almost identical to Python dictionaries and lists. It has become the standard for web data, configuration files, and APIs.

The json module is in the standard library.

import json

trials = [
    {"participant_id": 1, "age": 22, "side": "left", "cue": "left", "valid": True, "correct": True, "rt": 342.7},
    {"participant_id": 1, "age": 22, "side": "right", "cue": "left", "valid": False, "correct": True, "rt": 412.3},
]

# Write to file
with open("posner_data.json", "w") as f:
    json.dump(trials, f, indent=2)

# Read from file
with open("posner_data.json", "r") as f:
    loaded_trials = json.load(f)

print(loaded_trials[0])
print(type(loaded_trials[0]["rt"]))
{'participant_id': 1, 'age': 22, 'side': 'left', 'cue': 'left', 'valid': True, 'correct': True, 'rt': 342.7}
<class 'float'>

Notice that unlike CSV, JSON preserves types. The float comes back as a float, the boolean as a boolean.

10.5.1 When to Use JSON Over CSV

JSON handles nested data naturally. Suppose you want to store metadata about the experiment alongside the trials:

experiment = {
    "experiment_name": "Posner Cueing Task",
    "date": "2024-01-15",
    "experimenter": "Dr. Smith",
    "parameters": {
        "stimulus_duration_ms": 100,
        "cue_stimulus_interval_ms": 200,
        "valid_cue_probability": 0.8
    },
    "trials": [
        {"participant_id": 1, "side": "left", "valid": True, "rt": 342.7},
        {"participant_id": 1, "side": "right", "valid": False, "rt": 412.3},
    ]
}

with open("experiment_full.json", "w") as f:
    json.dump(experiment, f, indent=2)

This would be awkward to represent in a flat CSV.

10.6 Pickle

Pickle serializes Python objects to bytes. You can save nearly any Python object—lists, dictionaries, custom classes, even functions—and load them back exactly as they were.

import pickle

trials = [
    {"participant_id": 1, "age": 22, "side": "left", "valid": True, "rt": 342.7},
    {"participant_id": 2, "age": 19, "side": "right", "valid": False, "rt": 412.3},
]

# Save
with open("posner_data.pkl", "wb") as f:  # Note: "wb" for write binary
    pickle.dump(trials, f)

# Load
with open("posner_data.pkl", "rb") as f:  # Note: "rb" for read binary
    loaded_trials = pickle.load(f)

print(loaded_trials[0])
{'participant_id': 1, 'age': 22, 'side': 'left', 'valid': True, 'rt': 342.7}

10.6.1 When to Use Pickle

Pickle is excellent for:

  • Quick saves during analysis (“checkpoint” your work)
  • Saving complex Python objects that do not map to CSV or JSON
  • Caching intermediate results

10.6.2 When Not to Use Pickle

Warning

Security: Never unpickle data from untrusted sources. A malicious pickle file can execute arbitrary code when loaded.

Portability: Pickle files are Python-specific. You cannot open them in R, Excel, or other tools.

Versioning: A pickle created with one version of a library may not load with another version.

Use pickle for internal, temporary storage. Use CSV or JSON for sharing and archiving.

10.7 SQLite

As datasets grow, the approaches above start to strain. Loading a million-row CSV into memory as a list of dictionaries is slow and wasteful. What if you only need the data from participant 47? You still have to load everything.

Databases solve this problem. They store data on disk in a format optimized for queries. You ask for what you need, and only that data is loaded.

SQLite is a database that:

  • Comes with Python (the sqlite3 module is standard library)
  • Requires no server installation
  • Stores everything in a single .db file
  • Uses real SQL syntax that transfers to PostgreSQL, MySQL, and other databases

10.7.1 Creating a Database and Table

A database contains tables. A table is like a CSV file with a defined structure called a schema. The schema specifies column names and types.

import sqlite3

# Connect to database (creates file if it doesn't exist)
conn = sqlite3.connect("posner.db")
cursor = conn.cursor()

# Create table with schema
cursor.execute("""
    CREATE TABLE IF NOT EXISTS trials (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        participant_id INTEGER,
        age INTEGER,
        side TEXT,
        cue TEXT,
        valid INTEGER,
        correct INTEGER,
        rt REAL
    )
""")

conn.commit()

The schema declares:

  • id: an auto-incrementing primary key (you do not supply this)
  • participant_id, age: integers
  • side, cue: text
  • valid, correct: integers (SQLite has no boolean; use 0/1)
  • rt: real number (float)

10.7.2 Inserting Data

trials = [
    (1, 22, "left", "left", 1, 1, 342.7),
    (1, 22, "right", "left", 0, 1, 412.3),
    (1, 22, "left", "right", 0, 0, 523.1),
    (2, 19, "left", "left", 1, 1, 298.4),
    (2, 19, "right", "right", 1, 1, 287.2),
    (2, 19, "left", "right", 0, 1, 445.6),
]

cursor.executemany("""
    INSERT INTO trials (participant_id, age, side, cue, valid, correct, rt)
    VALUES (?, ?, ?, ?, ?, ?, ?)
""", trials)

conn.commit()

The ? placeholders protect against SQL injection and handle type conversion.

Warning

If you try to create the table multiple times you may get some errors. If that happens just delete the db file and start fresh.

10.7.7 Building a Schema From Existing Data

When you download a dataset, you need to design a schema. This means looking at the data and deciding:

  1. What are the column names?
  2. What type is each column?

Here is a systematic approach:

import csv

# Suppose you have a CSV file and want to figure out the schema
# First, look at the headers and a few rows

# For demonstration, let's create a sample CSV
sample_data = """participant_id,age,response,score
101,23,agree,4.5
102,19,disagree,2.1
103,31,neutral,3.0
"""

with open("sample_survey.csv", "w") as f:
    f.write(sample_data)

# Now examine it
with open("sample_survey.csv", "r") as f:
    reader = csv.DictReader(f)
    rows = list(reader)

print("Columns:", rows[0].keys())
print("First row:", rows[0])
Columns: dict_keys(['participant_id', 'age', 'response', 'score'])
First row: {'participant_id': '101', 'age': '23', 'response': 'agree', 'score': '4.5'}

From this inspection:

  • participant_id: looks like an integer
  • age: integer
  • response: text
  • score: float (has decimal)

The schema would be:

CREATE TABLE survey (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    participant_id INTEGER,
    age INTEGER,
    response TEXT,
    score REAL
)

10.9 Summary

Method Pros Cons Best For
Dictionary Native Python, intuitive Memory-only Runtime data
CSV Universal, human-readable No types, flat only Sharing, archiving
JSON Preserves types, nested data Verbose for large data Config, APIs, metadata
Pickle Any Python object Python-only, security risk Checkpoints, caching
SQLite Scalable, real queries, portable Learning curve Large datasets, complex queries

The progression through this chapter mirrors a typical research workflow: you start with data in memory (dictionaries), save it for sharing (CSV), add metadata (JSON), checkpoint your analysis (pickle), and eventually scale up to a database (SQLite) when the data grows.
